> 本文档的价值在于**诚实暴露弱点**。面试时被问出来很被动，主动写出来反而是加分项。
> 每条 badcase 都配一个回归用例（见 `tests/contract/`），所以它们不会再次发生。

## 一、真实失败模式（从飞书错误码反推）

以下三条不是假设，是 LLM 与脚本调用多维表格 API 时**最高频**的真实失败。

### 1. 单选字段传数组→ `1254062`

```
❌ 错：{"站点": ["US"]}
✅ 对：{"站点": "US"}
```

飞书的多选字段（type 4）要数组，**单选字段（type 3）要字符串**。
而人的直觉、以及多数 LLM 的直觉，都是「多维表格里的选项 → 应该是列表」。

**这是最容易踩的一条**，因为多选和单选在 UI 上看起来几乎一样。

**BasePilot 的处理**：`coerce.py` 允许调用方传 `["US"]`（单元素数组），
内部自动拍平为 `"US"`。**入口宽容，出口严格**。

### 2. 日期传秒级时间戳 → `1254064`

```
❌ 错：{"复核日期": 1674206443}        # 10 位= 秒
✅ 对：{"复核日期": 1674206443000}     # 13 位 = 毫秒
```

JavaScript 的 `Date.now()` 返回毫秒，但 Python 里的 `time.time()` 返回**秒**。
跨语言调用时极易搞错，且**差 1000 倍**，错出来的日期落在 1970 年附近，
在台账里看起来像"很老的记录"，排查起来很费时间。

**BasePilot 的处理**：`coerce.py` 接受 ISO 字符串（`"2026-10-18"`）、
`"YYYY-MM-DD"`、秒级时间戳、毫秒时间戳，内部统一转13 位毫秒。

### 3. 人员字段传字符串 → `1254066`

```
❌ 错：{"负责人": "张三"}
❌ 错：{"负责人": "ou_xxx"}
✅ 对：{"负责人": [{"id": "ou_xxx"}]}
```

必须是**数组对象**，而且**只支持 `id` 参数** —— 传 `name`、`open_id`、`union_id` 都失败。
清空该字段要传 `null`（不是空数组）。

**额外的坑**：跨应用场景下 `open_id` 会失效，需要用 `user_id`。

## 二、已知限制（明确划边界）

### API 层

| 限制 | 说明 |
|---|---|
| **不支持并发写同一张表** | 官方错误码 `1254291` / `1254607`。BasePilot 用 per-table 串行队列 + 0.5s 节流规避，但**多个进程同时写同一张表仍会冲突** |
| **不可写字段** | 公式(20)、查找引用(19)、创建时间(1001)、修改时间(1002)、创建人(1003)、修改人(1004)、自动编号(1005)、按钮(3001) —— 这些**只能算，不能写** |
| **附件两阶段** | 附件不能直接传本地路径，必须先 `drive/v1/medias/upload_all` 拿 `file_token`，且要求应用对该表有管理权限 |
| **高级权限下的空结果** | 表开了高级权限时，调用成功但可能**返回空数据**而非报错 |
| **跨域数据源同步的表** | 从其他数据源同步的表**不支持增删改** |
| **`batch_delete` 上限存在官方文档分歧** | 接口页正文写 500 条，错误码 `1254104` 描述写 1000 条。**取保守值 500**，做成可配置常量。理由见 ADR-003 |

### 本项目明确不做（Non-goals）

| 不做 | 理由 |
|---|---|
| 删除整个多维表格 | 不可逆，风险远高于收益 |
| 授予 / 变更权限 | 越权操作，应由表owner 在界面完成 |
| OAuth 授权流程 | 本项目定位是**企业内部工具 + 开源交付包**，不需要对外分发 |
| 直接发送飞书消息 | 消息发送涉及外部可见的副作用，应由上层决策后调用 |
| 事件订阅（长连接） | 需要公网与连接数管理，且**不解决当前核心痛点（写入可靠性）**。写进 ADR-006 说明什么条件下做 |

> **主动划边界比假装覆盖更可信。** 面试时"这个我不做，因为X"比"这个我都能做"更显专业。

## 三、官方文档本身的坑

### 1. `batch_delete` 上限不一致

- 接口页正文：「单次调用最多删除 **500** 条记录」
- 错误码 `1254104` 描述：「单次添加记录最多 **1000** 条」

**处理**：取保守值 500（`config.BATCH_DELETE_MAX`），做成可配置常量。
超限只会导致整批失败，而保守值只多一次请求 —— **失败比慢更贵**。

### 2. token 刷新的"无效区间"

官方说明「剩余有效期小于 30 分钟时返回新 token，**大于等于 30 分钟时返回原有 token**」。
这意味着：在剩余 40 分钟时触发刷新，**拿到的还是同一个 token**，
这次调用白白消耗了配额却没延长有效期。

**处理**：`TOKEN_REFRESH_THRESHOLD = 1800`（正好 30 分钟），
既落在官方规定的换发区间内，又不做过早的无效刷新。见 `auth.py`。

## 四、跑不起来的场景

| 场景 | 原因 | 处理 |
|---|---|---|
| `make live-smoke` 报鉴权失败 | 未配置 `.env` 或应用未发布 | 报错信息直接指向 `.env` 与「应用版本需管理员审核」 |
| `make live-smoke` 报 403 | 多维表格未授权给应用 | 报错信息给出「···」→「更多」→「添加文档应用」四步操作 |
| 写入报`1254036` 副本复制中 | 该表正在复制，异步操作 | 长退避重试（3s/6s/12s，最多5 次），仍失败则提示等复制完成 |

>这三条都是**客户现场会遇到的真问题**，所以 `errors.py` 把现场动作写进了 `guidance`，
> `docs/delivery/troubleshooting.md` 由 `errors.py` 自动生成，保证两者零漂移。

## 五、已知会漂移的数字

`eval/reports/eval_report.json` 里的指标随代码演进变化。
README 证据卡由 `make evidence` 从该文件生成，**禁止手写**。
若README 数字与报告不一致，CI 会红。

这是本项目的一条铁律：**交付承诺必须是可复现的数字，不是漂亮话。**
